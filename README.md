# 20轴伺服控制与故障诊断仿真（C++17）

这是一个**仅用于学习的纯软件仿真**，不连接真实电机，也**不是经过安全认证的机器人控制器**。可直接在 Ubuntu 24.04 / WSL Ubuntu / Linux 运行。数据为合成仿真，不是 KUKA、优必选或某款舵机实测参数。

## 1. 项目包含什么

- 20 个不同的关节：每关节不同惯量 `J`、黏性阻尼 `D`、库仑摩擦、转矩限制、转矩斜率限制、速度限制。
- 简化动力学：`J*q_ddot = tau - D*q_dot - tau_c*tanh(q_dot/0.025)`；显式考虑通信延迟与力矩斜率限制，用半隐式 Euler 更新。
- 1 ms 统一仿真控制周期；共用五次多项式轨迹，允许不同目标角度。
- 每个关节有一个离散 PID（D 使用目标速度与实际速度）+ 动力学前馈 + 抗积分饱和。
- 单独 20 路命令延迟队列：每条指令延迟 1–4 ms，并有可复现的 +2 ms 延迟扰动；每个包有序号，避免过期包覆盖新包。
- 正常工况；第 8 关节机械卡滞；中央控制器心跳停止；第 13 关节驱动器心跳停止。
- 软件监督器：控制器心跳超时、驱动器心跳超时、命令看门狗超时、持续位置跟踪误差、位置/速度越限、无效数值检查；故障使**整组进入模拟安全减速**。
- 驱动器级本地看门狗：命令超过 45 ms 未更新，不再继续无条件执行旧转矩，而使用模拟的本地速度阻尼制动。
- 安全减速持续超时转入 `ESTOP` 状态标签（只表示**仿真软件状态**，不是实际硬件急停、STO或SS1）。
- 1 ms 时钟调度的实测迟到量与周期偏差：`--realtime` 下由本机 `steady_clock` 测量。非实时快速仿真对这两个值写为空，不生成虚构抖动数据。
- CSV 日志、事件日志、到达时间统计和 Matplotlib 图表。

## 2. 一分钟启动

```bash
cd servo20_demo
sudo apt install -y build-essential cmake python3-matplotlib
cmake -S . -B build
cmake --build build -j

# 正常工况：在真实墙上时间按 1 ms 周期执行 4.5 秒，测量当前环境的调度抖动
./build/servo20 --scenario nominal --realtime --out results

# 故障注入：快速数值仿真，不提供调度抖动指标
./build/servo20 --scenario jam --out results
./build/servo20 --scenario controller_heartbeat --out results
./build/servo20 --scenario drive_heartbeat --out results

python3 tools/plot_results.py --input results --output plots
```

不想安装 CMake 时：`g++ -std=c++17 -O2 -Wall -Wextra src/main.cpp -o servo20`，然后使用 `./servo20`。运行 `./build/servo20 --help` 查看命令选项。

## 4. 重点阅读顺序

1. `ref_at()`：共同的运动时间轴、五次多项式、速度与加速度前馈。
2. `Joint::simulate()`：一自由度动力学、执行器限幅、摩擦与故障卡死模型。
3. `PID::update()`：离散反馈、抗积分饱和、力矩限制、模型前馈。
4. `DelayLine`：有限容量命令队列、延迟、消息序号和迟到包处理。
5. `run()`：所有关节的统一控制循环、控制器/驱动器心跳、故障注入。
6. `trigger` 与 `Joint::simulate(...,safe_brake)`：软件看门狗与故障后的整体降速行为。
7. CSV统计：真实到达时间 = 角度与速度同时进入容差区间，并保持 40 ms；实际到达时间差 = 最慢减最早。指令同时完成 ≠ 实际同时到达。

## 5. 示范性故障及阈值（可自行调节）

| 机制 | 代码中的阈值 | 说明 |
|---|---:|---|
| 控制器心跳超时 | 50 ms | 心跳通常每 10 ms 刷新；超时触发组级停机 |
| 驱动器心跳超时 | 50 ms | 监控每轴在线状态；第 13 轴可模拟故障 |
| 驱动器命令看门狗 | 45 ms | 新指令迟迟不到时，由**驱动器本地模型**开始速度阻尼制动 |
| 跟踪误差 | 0.065 rad 持续 60 ms | 用于发现关节卡滞；避免瞬时误差直接误报 |
| 模拟减速时限 | 0.8 s | 时间内未实现低速，转 `ESTOP` 软件状态 |
| 判定到达 | 位置误差 < 0.006 rad、速度 < 0.014 rad/s，持续 40 ms | 到达时间由测量决定 |

所有数值都是演示设置，不应作为实际机器人的安全阈值。真实阈值须由风险评估、设备能力、动力学与测试确定。

## 6. 图表怎么看

- `tracking_nominal.png`：20轴正常情况下期望-实际的跟踪误差。
- `tracking_jam.png`：第8轴卡滞引发误差增加与组级安全停止。
- `arrival_times_nominal.png`：目标时刻为3.25 s；显示每轴**实际稳定到位**时刻相对目标时刻偏差及最早/最晚间隔。
- `wakeup_lateness_nominal.png`：1 ms 定时唤醒实际迟到多少微秒。
- `period_error_nominal.png`：实际相邻唤醒间隔与 1000 微秒的偏差。
- `heartbeat_watchdog.png`：控制器心跳年龄跨越50 ms阈值后触发安全停止。
- `jam_motor_torque.png`：卡滞关节仍可能持续产生电机转矩；本仿真**不等于电流实测**。

**注意**：WSL/Linux普通用户进程未必能保证严格1 kHz硬实时。统计的是**本机调度表现**，不是EtherCAT设备同步误差，也不能据此宣称安全实时性；如需准确定量，应在目标设备和负载条件下测量最坏执行时间、调度延迟、通信延迟及丢截止期次数。相应思路参考 `clock_nanosleep(2)` 的绝对时刻调度和 ROS 2 实时编程文档。

## 7. 这个示例还不具备的生产级能力

- 没有真实编码器/电流回路/驱动器API，也没有机器人碰撞检测、重力载荷和机械制动器模型。
- 把关节卡滞简化成位置冻结，不能用来预测真实碰撞力矩或过流风险。
- `SAFE_STOP`仅是在模拟关节上施加阻尼转矩，不等于IEC 61800-5-2的SS1/SS2/STO安全功能；更不能据此给真实机械臂设计人员保护等级。
- 没有经过形式化验证的独立安全控制器、双通道急停、硬件看门狗、安全编码器、失效安全继电器。
- 没有真实通信时钟同步。20路指令使用同一仿真时间参考，**不等于真实硬件在同一个时钟沿生效**。
- 对于有重力的机械臂，盲目切断转矩可能造成下坠，需要根据设备手册及制动器架构选择合适的安全停车方式。
- 软件演示为了易读采用单线程顺序执行；实际系统应将实时伺服、通信、规划、日志、安全控制分层并进行硬件在环验证。

## 8. 工程扩展建议

1. **最先做**：改成3个线程：统一实时控制线程、轨迹规划线程、日志/诊断线程，用预分配单生产者单消费者缓存交换数据。
2. 给每个驱动器增加`command_id`、`planned_execution_time`，区分**收到命令**和**命令实际执行**；模拟同步时钟误差。
3. 做PID参数扫描、仿真带宽测试；增加编码器跳变、通信丢包、摩擦上升、温度过高、总线过载等故障。
4. 加入重力和机械耦合，模拟故障停车时如何保持负载；再考虑硬件在环测试。

## 9. 回归测试

全部运行完之后执行：

```bash
python3 tools/check_results.py
```

它检查：正常工况全部到位，卡滞触发跟踪误差保护，两个心跳丢失场景触发对应看门狗，异常工况进入模拟停止状态；结果文件均具有正确的采样点数。

补充：在故障工况的CSV中，`q_ref_i`字段继续保留**原定轨迹**供离线分析，但安全停机后这条轨迹不再被控制器跟踪。`tracking_*`图只展示停机前后很短一段；`braking_*`图单独验证停车速度的下降，避免将原定轨迹的后续误差误解为安全制动器的控制误差。
